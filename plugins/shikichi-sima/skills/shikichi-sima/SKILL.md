# shikichi-sima — 測量図から敷地データを作る

**合言葉は「測量図から敷地データ作って」。** 「SIMA作って」「敷地を CAD に入れたい」でも使う。

測量図の座標を読み取り、CAD に読み込めるファイルにする。道具は `sima_gen.py`。
辺の長さと面積を図面の値と照らし、1つでも合わなければ何も書かない。

座標の写し間違いが一番怖い。面積や辺がズレたまま配置図が進むからだ。
だから **使う人の目で1回、道具の検算で1回**、2段で止める。どちらも飛ばさない。

## 使う時・使わない時

使う。

- 座標求積表(点名と X・Y の座標が並んだ表)が載った測量図があり、CAD に敷地を入れたい時
- 宅地と前面道路をまとめて入れたい時。地番を分けて1つのファイルにする

使わない。

- 座標が載っていない図面しか無い時。辺の長さだけの図面など。CAD の敷地入力で直接引いてもらう
- 測量した事務所から SIMA ファイルをもらえている時。自作せず、それをそのまま使う。現物が一番確か
- 建物や現況の線を入れたい時。この手順書は敷地の外周だけを扱う

## 読み込める CAD

- **実機で確かめたのは ARCHITREND ZERO の SIMA 読み込みだけ**。2件続けて一発で通った
- ほかの CAD の SIMA 読み込みと、DXF の読み込みは未確認。初めての CAD では、使う人に1回読み込んでもらい、形と寸法を確かめてから本番に使う
- ARCHITREND ZERO では、DXF は敷地にならず線として入るだけ。敷地として入れるなら SIMA を使う

## 手順

1. 測量図を受け取る。PDF か画像。
2. 座標求積表を読む。読み取る物は次のとおり。

   - 地番ごとの点の並び。表の順が、外周を回る順
   - 点名・X・Y。**X が北、Y が東。** マイナスの記号を落とさない
   - 距離(次の点まで)と地積。検算に使うので、載っていれば必ず写す
   - 宅地と道路のように地番が複数あれば分ける。2つの地番で共有する点は、同じ点名で書く

   かすれて読めない数字は、推測で埋めない。表の中に「？」のまま出す。

3. 読み取った物を表にして画面に出す。地番ごとに1つの表にする。

   | 点名 | X(北) | Y(東) | 次の点までの距離 |
   |---|---|---|---|

   表の下に地積を書く。そして「図面と見比べて、合っていたら『合ってる』と言ってください」と聞く。
   **『合ってる』が返るまで、ファイルを1つも書かない。** 直しが来たら表を直して、もう一度見せる。

4. JSON を書く。置き場は、いま話している仕事の置き場の `docs/`。そういう置き場が無いフォルダなら、いま開いているフォルダの中のどこに置くかを1回聞く。名前は `<日付>_<現場名>.json`。
   どの仕事の書類か決まらない時だけ、1回聞く。形は下の「JSON の形」。
5. 道具を叩く。

   ```
   python "${CLAUDE_PLUGIN_ROOT}/scripts/sima_gen.py" <JSON のパス>
   ```

   DXF も欲しいと言われたら `--dxf` を足す。CAD の原点近くに置きたい時は `--dxf --origin first`。
   出力は JSON と同じ場所に、同じ名前で `.sim`(と `.dxf`)ができる。

6. 結果で分ける。

   - **合格**(`[OK] 読み戻し検査 合格`): 検算の OK の行と、出力先を見せる。次の手順7を添える
   - **検算に落ちた**(`[STOP]`): NG の辺と面積の差を見せる。NG の辺の両端の点を図面でもう一度読み、使う人にもその行を見てもらう。直したら手順3からやり直す。図面の値どうしが食い違っていると分かったら、測量した事務所に確かめるよう伝える。**検算を飛ばす道は無い**
   - **入力の誤り**(`[ERROR]`): JSON の形の誤り。自分で直して叩き直す。使う人に JSON を見せない
   - **既にファイルがある**: 置き換えてよいかを使う人に聞く。良いと言われたら `--overwrite` を足して叩き直す

7. CAD への読み込み方を伝える。
   ARCHITREND ZERO は「敷地」→「敷地」→「SIMA敷地読み込み」。ダイアログで地番を選ぶ。
   ほかの CAD と DXF は未確認なので、初めて読み込んだ時は、地番の数・北の向き・辺の長さ1本を確かめてもらうまで本番に使わない。

## JSON の形

```json
{
  "genba": "〇〇様邸 〇〇町1丁目 3号地",
  "chiban": [
    {
      "name": "3号地",
      "area": 150.23,
      "points": [
        ["K1", -12345.678, -23456.789, 12.34],
        ["K2", -12333.338, -23456.789, 12.18]
      ]
    }
  ]
}
```

- `genba` は現場名。SIMA の先頭に入る
- `name` は地番名。ARCHITREND ZERO の読み込みダイアログに出る
- `area` は図面の地積(m2)。検算に使う。無ければ書かない
- 点は `[点名, X(北), Y(東), 次の点までの距離, 標高]`。距離が無ければ `null`。標高は省いてよい
- 点は外周を回る順に並べる。最後に最初の点を繰り返さない
- 点名と地番名は、全角10文字(半角20文字)まで。`,` は使えない
- 座標は測量図の数字のまま(m)。単位や原点を変えない

## 検算の中身

| 項目 | 照らす先 | 許す差 |
|---|---|---|
| 辺の長さ | 図面の距離の欄 | 0.011 m(図面が小数2桁なので丸めの分) |
| 面積 | 図面の地積 | 0.02 m2 |
| 書いたファイル | 読み戻して、行の数・桁の位置・閉じた線・頂点の数と位置 | ― (道具の内側の形の検査。CAD で読めることの保証ではない) |

1つでも落ちたら、SIMA も DXF も書かない。

## 押さえどころ

- 使う人に見せるのは、読み取った表・検算の結果・出力先・読み込み方。コマンドと JSON は見せない
- DXF の単位は mm。x が東、y が北。読み込む側の CAD の単位を mm にしてもらう
- お客様の土地の情報なので、社外に出したくないと言われたら `private/` に置く
- SIMA の書式は ARCHITREND ZERO で実機合格した物を固定している。道具の書式は直さない

## 入れた時・外す時

入れた時は1回動かして、結果を見せる。架空の土地のテストが通れば、道具は動いている。

```
python -m pytest "${CLAUDE_PLUGIN_ROOT}/tests" -q
```

外す時は、プラグインを外すだけでよい。使う人のフォルダには、書き出した `.json`・`.sim`・`.dxf` の他に何も残していない。

- コマンドで入れた時(`shikichi-sima@shikichi-sima`):

  ```
  claude plugin uninstall shikichi-sima@shikichi-sima
  ```

- フォルダごと配られて `.claude/skills/shikichi-sima/` に置かれている時(`shikichi-sima@skills-dir`): そのフォルダを消す

会社のフォルダを git で管理しているなら、`.gitattributes` に `*.sim binary` と `*.dxf binary` の2行を入れておく。既定の改行変換のままだと、別の機械で取り出した `.sim` の CRLF が崩れて読み込めなくなる。
